# ML Component

Dataset preparation, training, evaluation and model export for the VisionOps safety detection model.

## Problem and dataset

The model detects construction site PPE compliance in images and video frames. It is trained on the public [Construction Site Safety Image Dataset](https://universe.roboflow.com/roboflow-universe-projects/construction-site-safety) from Roboflow Universe, which covers ten classes:

`Hardhat, Mask, NO-Hardhat, NO-Mask, NO-Safety Vest, Person, Safety Cone, Safety Vest, machinery, vehicle`

Any class prefixed with `NO-` represents a safety violation. This mapping is what the backend uses to flag `is_violation = true` on stored detections and to compute a compliance score for the dashboard.

## Model

[YOLOv8](https://github.com/ultralytics/ultralytics) (nano/small variant) was chosen over heavier two-stage detectors because:

- It runs fast enough for near real time video inference on a single CPU or a small GPU, which matters for a monitoring product where footage is continuous.
- The `ultralytics` Python package exposes training, validation, export and inference through one consistent API, so the backend can reuse the exact same inference call used during evaluation with no custom pre or post processing code to keep in sync.
- Pretrained COCO weights transfer well to PPE detection with a moderate amount of fine-tuning data, since classes like `Person` and `vehicle` are already close to COCO categories.

## Pipeline

```
scripts/download_dataset.py   -> ml/data/raw       (raw images + YOLO labels)
scripts/prepare_dataset.py    -> ml/data/processed  (normalized train/val/test split)
src/train.py                  -> ml/runs/<name>     (training checkpoints and logs)
src/evaluate.py                -> ml/reports         (metrics.json, metrics.md, confusion_matrix.png, pr_curve.png)
src/export_model.py            -> ml/models          (production checkpoint served by the backend)
src/predict.py                 -> ml/reports         (sample annotated predictions, demo.gif)
```

## Setup

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## Reproducing the full pipeline

```
python scripts/download_dataset.py --source roboflow --output-dir data/raw
python scripts/prepare_dataset.py --raw-dir data/raw --output-dir data/processed
python src/train.py --model yolov8n.pt --epochs 100 --imgsz 640
python src/evaluate.py --weights runs/visionops_ppe/weights/best.pt
python src/export_model.py --weights runs/visionops_ppe/weights/best.pt
```

`download_dataset.py --source roboflow` requires a free API key from [app.roboflow.com](https://app.roboflow.com), exported as `ROBOFLOW_API_KEY`.

## Smoke test without credentials

For CI or a first quick check that the pipeline runs end to end without any external account, use the `sample` source. It downloads COCO128 (a tiny, public, no-auth 128 image subset of COCO) and trains for a couple of epochs. This validates the code path, not PPE accuracy:

```
python scripts/download_dataset.py --source sample --output-dir data/raw
python scripts/prepare_dataset.py --raw-dir data/raw --output-dir data/processed
python src/train.py --model yolov8n.pt --epochs 3 --imgsz 640 --run-name smoke_test
```

## Results

See [reports/metrics.md](reports/metrics.md) for the full per class table and the root [README](../README.md#results) for the embedded summary and artifacts. Evaluation artifacts in `reports/` (confusion matrix, PR curve, sample predictions, metrics files) are regenerated by `src/evaluate.py` and `src/predict.py`, never hand edited.

## Serving

`export_model.py` copies the chosen checkpoint into `models/`. The backend's `MODEL_PATH` environment variable points at that file; see [backend/README.md](../backend/README.md) for how the API loads and calls the model.
